## 3. TTA 结果

### 3.1 实现方式（关键正确性检查）

- **TTA-A (hflip)**：`cv2.flip(im_5ch, 1)` —— 对**合并后的 5 通道图整体**做水平翻转，`[B,G,R,IR,D]` 五个通道用同一算子变换，**物理上不可能出现 RGB 翻转而 IR/Depth 不翻转**。翻转图独立走 `_preprocess_rect` 后推理，`scale_boxes` 用其自身 `ratio_pad` 回到「翻转图原图坐标系」，再用 `x1' = W − x2, x2' = W − x1`（W = 原图宽）还原到原图坐标系。逐类 NMS（IoU=0.7）合并。
- **TTA-B (multiscale)**：0.8× / 1.0× / 1.2× → imgsz = 1024 / 1280 / 1536，各自独立 `_preprocess_rect` + 推理，各尺度用**自身** `ratio_pad` 映射回同一原图坐标系后逐类 NMS 合并。

**TTA 机制诊断**：
- HFlip 的 mAP75 塌陷最明显（0.62455 → 0.56887，**−0.056**），即 IoU=0.7 的逐类 NMS 合并把「原图正确框」与「翻转稍偏框」二选一时保留了定位更差的那个，**牺牲定位精度换召回**。tricycle 从 0.8052 崩到 0.7012 是典型受害者。
- MultiScale 引入 **+62% 框数**（4824 → 7835），Precision 从 0.83887 掉到 0.81310，mAP50 掉 0.020。多尺度确实补了 rc（ball 小幅上升），但代价是低置信框长尾。
- **结论：TTA 不通过一级判据（fork 口径），且 HFlip 在两种口径下都劣于 baseline。TTA 不可作为提交候选。**

## 4. Ensemble 结果

### 4.1 实现方式

模型 A（RGBID，5ch `[B,G,R,IR,D]`）与模型 B（F4，4ch `[B,G,R,D]`）**各自独立推理、各自独立 `_preprocess_rect`**（两个 loader 独立读取，均映射回**同一原图坐标系**），保留 class id 后拼接，再做统一逐类 NMS（IoU=0.7）。

权重搜索通过**置信度加权**实现：模型 A 的 conf × ratio，模型 B 的 conf × 1，然后统一 NMS —— 加权只改变合并时的优先级，不改变框的几何。

> ⚠️ **副作用（重要）**：2:1 与 3:1 的落盘 TXT 中会出现 **conf > 1.0**（2:1 有 2351 行，3:1 有 2486 行，最大 2.9212）。这些 TXT **不是合法提交文件**，仅用于离线排序审计。1:1 不加权，conf ∈ [0,1]，格式合法。

## 5. 互补性审计（§9，核心发现）

匹配口径：原图坐标 + 逐类 + IoU ≥ 0.5 贪心匹配。

| 统计项 | 数值 |
|---|---|
| GT 对象总数 | 2807 |
| 两模型都命中 (both) | 2171 |
| **仅 RGBID 命中** | **117** |
| **仅 F4 命中** | **119** |
| 两模型都漏 (neither) | 400 |

| 模型 | 预测框 | TP | FP | 重复检测 |
|---|---|---|---|---|
| RGBID | 4824 | 2288 | 2536 | 0 |
| F4 | 5152 | 2290 | 2862 | 0 |
| **Ensemble 2:1** | 7031 | 2395 | **4636** | 0 |

- **Ensemble 相对 RGBID 新增 TP：109**（理论上限 119，即回收了 F4 独有命中的 **91.6%**）
- **Ensemble 相对 RGBID 新增 FP：2100**（预测框总数 +46%）

### 5.1 互补性结论

> **F4 确实提供了 RGBID 没有的信息。** 两个模型在 GT 层面近乎对称互补（117 vs 119，不是单边附庸），Ensemble 把 RGBID 的漏检从 517 降到 408。这不是「重复框 + FP」，而是真实的召回互补。

**但代价极大**：用 +2100 个 FP 换 +109 个 TP（约 19 FP / 1 TP）。这笔交易在**召回敏感**的评价下成立，在**精度敏感**的评价下不成立 —— 这正是 §6.1 两种口径结论相反的根因。

### 5.2 重复框 / 漏检变化

- 重复检测（同一 GT 被多个预测框命中）：三个模型均为 **0**，逐类 NMS 去重有效，无冗余框堆积。
- 漏检变化：RGBID 漏 517 个 GT（117 被 F4 补上 = F4 独有；400 两者都漏）。Ensemble 后漏检降至 408。
- 新增 FP 主要来自 F4 带入的低置信框：Ensemble 框数 7031 ≈ RGBID 4824 + F4 5152 − 合并去重 ~2945。

### 6.1 误差分析（§6）

### 6.2 重点类分析

- **person / sign**：两个 TTA 和三个 Ensemble 在**官方口径下全部上升**，是最一致的受益类（person 0.4394→0.4530~0.4604；sign 0.3784→0.3862~0.3961）。与 F4 在 person 上本就更强（0.4455 > 0.4394）一致 —— 这是 Ensemble 真实互补的主要来源。
- **ball**：MultiScale 与 Ensemble 均上升（0.4139→0.4277~0.4346），HFlip 下降。小目标受益于多尺度/多模型。
- **bicycle**：Ensemble 微升（→0.3876~0.3889），基本持平。
- **boat**：**分歧最大**。Ensemble 1:1 下降（0.4863→0.4694），2:1/3:1 上升（→0.4892/0.4953）。这是 1:1 被判 2 类下降的主因。
- **tricycle**：1:1 暴升 +0.0495，2:1/3:1 完全不变（0.8020），HFlip 崩塌（0.7020）。说明 F4 在 tricycle 上提供了大量独有贡献，但只有在等权时才能压过 RGBID 的框。

## 7. Decision

### 7.1 正式判定：`KEEP_RGBID`

依据任务 §4 / §11 的判据：

1. **TTA**：一级判据（mAP50-95 > baseline）在 fork 口径下**失败**（HFlip −0.01703，MultiScale −0.01445）。HFlip 在两种口径下均为负；MultiScale 在官方口径下仅 +0.00432 且逐类 3 降，属边缘不达标。→ **TTA 淘汰**。
2. **Ensemble**：在 fork 口径（= 所有历史基线数字所用口径）下**全部为负**（−0.00918 ~ −0.00995），且逐类检查显示大部分类别下降 → 按 §4 三级条件应标记为 **`unstable`**，不满足「稳定超过 RGBID」。
3. §12 规定：发现不确定性应立即停止并报告，不得自行猜测。**口径选择正是一处我无权单方面裁决的不确定性**。

→ 因此正式输出 **`KEEP_RGBID`**。**不建议在本轮授权线上提交。**

| ens 3:1 | **−0.00942** | **+0.00901**（10 升 / 0 降） |
| ens 1:1 | −0.00918 | +0.00944（10 升 / 2 降） |

**双方都非噪声**（阈值鲁棒，见 §6.3），差异来自两种 mAP 定义的固有特性：
- **fork** 用 `ramp` 尾部插值，对「最高召回处的精度」极其敏感 → 严厉惩罚 Ensemble 带入的低置信 FP 长尾。
- **官方** 尾部直接取 0（硬悬崖），R_max 越高越好 → 奖励 Ensemble 带来的召回扩展。

**已知的口径—线上校准关系**（两个数据点，仅陈述事实，**不预测线上成绩**）：

| 模型 | 本地官方口径 | 线上实际 | 差 |
|---|---|---|---|
| F4 RGBD | 0.49082 | 0.51051 | +0.01969 |
| RGBID | 0.50928 | 0.53180 | +0.02252 |

两个点都落在 +0.020 附近，**提示官方口径与线上同源**，而 fork 口径与线上没有已知的校准关系。若这一点成立，则 Ensemble 2:1 / 3:1 的 **+0.0085 / +0.0090（官方口径）** 才是与决策相关的数字。

**但我不会据此擅自改判**，原因有二：
1. 任务的全部基线数字（0.53273 / 0.55800）与判据阈值都建立在 fork 口径上，换口径等于换基准，应由你决定。
2. 本地 val 是训练集切分（同分布），测试集分布不同；+109 TP / +2100 FP 这笔交易在测试集上是否同样成立，**本地无法验证**。

### 7.3 若你选择按官方口径采纳，推荐方案

**`RGBID : F4 = 3:1`**，理由：
- 官方 mAP50-95 = 0.51829（+0.00901），**10 升 / 0 降**，最稳定之一；
- **Precision 反而上升到 0.84742**（baseline 0.83887），是唯一一个精度不降的融合方案 —— 说明它主要吸收 F4 的高置信框而非低置信噪声；
- 符合「不应让较弱的 F4 大量影响结果」的约束。
- 1:1 虽然官方总分略高（0.51872），但 **2 类下降**且增益高度依赖 tricycle 单类（+0.0495），稳定性不如 3:1。
