# F4 实验报告：YOLO11m RGBD 中期融合 @ imgsz=1280（严格单变量）

- **实验定义**：F4 = F1 唯一改动 `imgsz: 1024 → 1280`。其余一切超参与 F1 逐字节一致。
- **基线**：F1 = `urban_multimodal_det_e7_lr0half`（YOLO11m RGBD mid-fusion @1024，best mAP50-95=0.51955）。
- **结果目录**：`runs/urban_multimodal_det_yolo11_rgbd_f4_1280/`（独立目录，未 resume F1，从头训练）。
- **结论速览**：best mAP50-95 **0.53273**（+0.01318，+2.54%）；平台期稳定 +0.006~0.011；4 个小目标类全部上涨，直接印证分辨率假设。

---

## 1. F1 / F4 配置 diff（唯一变量）

对两份 `args.yaml` 做语义 diff，**唯一有实验意义的差别是 `imgsz`**：

| 字段 | F1（e7_lr0half） | F4（f4_1280） | 说明 |
|---|---|---|---|
| `imgsz` | 1024 | **1280** | ✅ 唯一实验变量 |
| `name` | urban_multimodal_det_e7_lr0half | urban_multimodal_det_yolo11_rgbd_f4_1280 | 仅目录命名，非超参 |
| `save_dir` | runs/…_e7_lr0half | runs/…_f4_1280 | 仅目录命名，非超参 |

其余**全部字节一致**：`epochs=300, patience=80, batch=8, lr0=0.005, lrf=0.01, momentum=0.937, weight_decay=0.0005, warmup_epochs=3, cos_lr=true, close_mosaic=10, amp=true, nbs=64, seed=42, optimizer=SGD, pretrained=yolo11m.pt, use_simotm=RGBD, channels=4, pairs=[visible,depth], box=7.5/cls=0.5/dfl=1.5, mosaic=1.0, erasing=0.4, auto_augment=randaugment` 等。

→ **单变量成立**。`name`/`save_dir` 只服务于「独立目录」要求，不构成超参改动。

## 3. GPU / batch / 有效 batch / 显存

- **GPU**：V100 32GB（云端 AutoDL，CUDA 12.1）。
- **batch=8**，`nbs=64` → `accumulate = round(64/8) = 8`，**有效 batch 恒为 64**（与 F1 完全一致）。
- **lr0 未动**（0.005）：因为 batch 与 F1 相同（都是 8），无需按 batch 缩放学习率；梯度累积自动补偿，`weight_decay` 亦按累积步数校正。
- **显存**：训练完整跑完 300 ep，**未 OOM**（云端验证通过，弥补了本地 CPU 无法测 VRAM 的空缺）。
- **计算量**：456.83 GFLOPs @1280（F1@1024 = 292.37，约为 F1 的 **1.56×**）。

## 4. 冒烟测试结果（开训前）

`scripts/f4_smoke_test.py`，**20 PASS / 0 FAIL**（本地 CPU，batch=2；batch=8@1280 在 CPU 上需 >20GB 内存会 segfault，属 CPU 内存上限而非代码/GPU 问题）。

覆盖项：RGBD 数据读取、4-channel 输入、1280 letterbox、mid-fusion 结构（SilenceChannel×2 + ADD×3）、forward（P3/P4/P5 = 160/80/40 @1280）、backward（**depth 分支 stem 确实收到梯度**，证明融合在训）、loss 有限为正、NMS 后处理可解析。唯一 SKIP 项为 VRAM 实测，已由云端训练成功反证。

## 11. 四个小目标类逐类结果（person / sign / bicycle / ball）

口径：复刻训练内置 val（conf=0.001 / iou=0.7 / max_det=300 / imgsz=1280）。F4 逐类为本地重跑 batch=4，F1 逐类为 batch=8（见末注）。

| 类 | 指标 | F1@1024 | F4@1280 | Δ |
|---|---|---|---|---|
| **person** | AP50-95 | 0.464 | 0.490 | **+0.026** |
| | P / R | 0.858 / 0.646 | 0.827 / 0.699 | −0.031 / +0.053 |
| **sign** | AP50-95 | 0.400 | 0.430 | **+0.030** |
| | P / R | 0.818 / 0.547 | 0.822 / 0.580 | +0.004 / +0.033 |
| **bicycle** | AP50-95 | 0.399 | 0.424 | **+0.025** |
| | P / R | 0.831 / 0.491 | 0.753 / 0.519 | −0.078 / +0.028 |
| **ball** | AP50-95 | 0.369 | 0.427 | **+0.058** |
| | P / R | 0.975 / 0.526 | 0.915 / 0.566 | −0.060 / +0.040 |

**规律**：4 个小目标类的 **Recall 全部上升**（+0.028 ~ +0.053），AP50-95 全部上涨（ball +0.058 最大，正是诊断中面积最小、漏检最重的类）；**Precision 多数下降**（bicycle −0.078、ball −0.060 最明显）。即：高分辨率框出了更多小目标（TP↑→R↑），但也带来更多低置信框（FP↑→P↓），Recall 增益主导 → mAP 净升。这与「硬漏检→分辨率/尺度」的诊断完全吻合。

## 12. 最优曲线稳定性

- F4 best=0.53273 @ep251，**是一个尖峰**：超出其 ±10 ep 均值（0.52413）达 **0.00860**；而 F1 best@ep287 只超出 ±10ep 均值 0.00340。
- 「落在 best ±0.005 内的 epoch 数」：F4 仅 **10/300**，F1 为 51/300 → 说明 0.53273 本身有运气成分，**不可直接按 +0.013 规划收益**。
- 但**平台期一致性抬高，且全程为正**（不是靠单点）：
  | 窗口 | F4 均值 | F1 均值 | Δ |
  |---|---|---|---|
  | ep200–250 | 0.52309 | 0.51224 | **+0.01085** |
  | ep250–300 | 0.52292 | 0.51583 | **+0.00709** |
  | ep290–300 | 0.51882 | 0.51368 | **+0.00513** |
  | 末 30 ep | 0.52191 | 0.51606 | **+0.00585** |
- **无异常发散**：`val/box_loss` 全程平坦（约 1.30–1.31），训练健康。
- 末段（ep291–300）两曲线同步下探 ~0.005，是 `close_mosaic=10` 的已知效应（ep290 关闭 mosaic 的尾部回落），非 1280 特有。

## 14. 是否继续 1280 方向 → **继续**

依据三条：
1. 增益不是单点运气——所有窗口 Δ 均 >0，平台期稳定 +0.006~0.011；
2. 逐类增益恰好落在诊断预言的 4 个小目标类（ball/sign/person/bicycle），机制自洽；
3. 无 loss 发散，代价只是 1.56× 计算量（456.83 vs 292.37 GFLOPs）。

**保留 1280 为新基线**，但后续规划收益按 **+0.006~0.011**（保守）而非 +0.013（尖峰）。

## 15. 下一步建议

按 `f1-error-diagnosis.md` 的排序，分辨率（①）已兑现，下一个杠杆是**容量（② YOLO11l）**，且正好针对本实验暴露的短板：1280 后 Recall 上来了但 **Precision 掉得明显（bicycle −0.078、ball −0.060）**——说明 m 量级在 1280 下已逼近其判别能力上限，加容量有望「保住 Recall、补回 Precision」。

- **主方案 F5 = YOLO11l RGBD mid-fusion @1280**（相对 F4 单变量：仅 scale m→l）。
  - 成功判据：mAP50-95 ≥ 0.540（若容量受限假设成立，可期待 +0.015~0.025，参照 E 系列 s→m 曾 +0.024）。
  - 代价：l@1280 计算量约为 m@1280 的 **4×**（~1.8k GFLOPs），V100 32GB 下 batch=8 大概率 OOM，需 `batch=2`（accumulate=32，有效 batch 仍 64，**lr0 保持 0.005 不动**），单 run 约 30h。若时间/显存不允许，退而 **YOLO11l@1024**（隔离容量变量，与 F1@1024 比，更便宜）。
- **并行廉价项 ⑤ 数据修复**（2 张 corrupt 图 + 40 个越界标签）——近零成本、与上述正交，可作为 F5 的独立对照顺带做；它改数据集，故**单独成实验**，不混入 F4 单变量结论。
- **不建议**：450 ep（F4 在 ep251 后已平台并小幅回落，延训无益，且 close_mosaic=10 尾部本就有回落）；P2/注意力/新 loss/TTA/conf 刷分——仍被 `f1-error-diagnosis.md` 第 1、2 条证伪或违规。
